## 작업 방식 (중요)
- **승인을 구하지 말고 끝까지 진행한다.** 각 항목을 완료하면 다음 항목으로 즉시 넘어간다. 사용자에게 "계속할까요?"라고 묻지 않는다.
- 각 항목마다: (1) 관련 기존 코드/데이터 모델 먼저 읽기 (2) 기존 코드 스타일(파일당 촘촘한 한 줄 스타일, CSS는 대응 `.css` 파일에 클래스로, 순수 로직은 `src/game/`에 분리하고 컴포넌트는 `src/components/`) 유지 (3) 정직하게 구현 — 실제로 안 되는 걸 되는 것처럼 문구만 그럴싸하게 쓰지 않는다 (GDD가 과장한 부분은 코드 주석으로 범위를 명시).
- 각 항목 완료 후 반드시: `npx tsc --noEmit -p .` → `npx vitest run` (전체 스위트 반드시 그린) → `npx vite build`. 하나라도 실패하면 다음 항목으로 넘어가지 말고 고친다.
- 새 로직에는 반드시 `renderToStaticMarkup` 기반 실제 내용 검증 테스트(장식이 아니라 진짜 상태 변화)를 추가한다. `WorldHub`처럼 내부 상태로 열림/탭이 결정되는 컴포넌트는 필요하면 `initialOpen`/`initialTab` 같은 테스트 전용 optional prop을 추가해 실제로 렌더되는 마크업을 검증할 것 (장식적 "안 터지는지"만 확인하는 테스트로 때우지 말 것).
- Browser 프리뷰(`preview_start`+`computer screenshot`)가 되면 각 항목마다 한 번 확인하되, 이 세션에서처럼 계속 타임아웃되면 무리하게 재시도하지 말고 텍스트 검증(`get_page_text`) + 테스트로 대체하고 다음 항목으로 진행한다.
- 각 항목이 끝날 때마다 커밋하지 말고(사용자가 명시적으로 커밋을 요청하기 전까지), 전체가 끝난 뒤 한 번에 변경사항을 정리해서 보고한다. 진행 중간중간 `mark_chapter`로 구간만 표시한다.

## 백로그 (우선순위 순 — 위에서부터 처리)

1. ✅ **훈련 미니게임에 콤보→필살기 연계 추가 (GDD 3.4)** — `src/game/finisher.ts` 순수 로직 + `game.ts` TRAIN 리듀서 연동 + `App.tsx` HuntGame 시각 연출(충전 유도 펄스, 필살기 발동 플래시). 테스트 12건 추가.
   `src/App.tsx`의 사냥/마법/휴식/약초 미니게임(`HuntGame`/`RestGame`/`MagicGame`/`HerbGame`)은 콤보만 세고 필살기 연출이 없다. 콤보가 임계치(예: 5)에 도달하면 "기 모으기"류 액션이 강조되고, 다음 입력이 크게 보너스를 받는 필살기 발동을 추가한다. `game.ts`의 `TRAIN` 리듀서에 필살기 배율을 반영하고, 최소 1개 미니게임(사냥부터)에 시각 연출을 넣는다. 순수 로직은 테스트로 검증.

2. ✅ **가방/드레싱룸/유전특성 UI 중복 정리** — `WorldHub`에 외부에서 특정 탭을 열도록 요청하는 `openSignal`/`openTab` prop 추가, `Root.tsx`가 신호를 중계, `LayeredHome`의 '성장'(bag) 패널에 "드레싱룸 · 유전 특성 보러가기" CTA 버튼 추가. 테스트 5건 추가.
   `home-panels.ts`의 'bag'(성장 기록) 패널은 텍스트 XP 목록만 보여주고, 실제 착용/유전특성은 `WorldHub`의 '수집' 탭에 따로 있다. 두 진입점을 하나의 일관된 동선으로 정리하거나(예: 'bag' 패널에서 드레싱룸으로 바로 이동하는 버튼 추가), 최소한 서로를 안내하는 링크를 추가한다.

3. ✅ **`attendance`(여정)/`mission`(가이드) 홈 패널 실질화 점검** — attendance/quest/outing/event/mail은 이미 실제 상태 기반이었음. `mission` 패널의 "4주 일정 완성"/"새로운 기억 만들기" 항목이 실제로는 절대 'done'이 되지 않던 하드코딩 버그를 고침(`state.week>=4`, `state.memories.length>0` 기준으로 실제 완료 반영). 테스트 1건 추가.
   `home-panels.ts`의 두 패널이 실제 상태를 반영하는지 재점검하고, 정적 문구로만 채워진 부분이 있으면 실제 계산값으로 교체한다.

4. ⏫ **3v3 파티 전투 시스템의 현실적 범위 확정 — 최초 (b) 보류 → 이후 별도 대규모 작업으로 완성.** 처음엔 (b) 보류를 선택(근거는 `NOTES.md` 참고). 이후 사용자가 "다음 대규모 작업 시작"을 요청해 별도 세션으로 진행: 신규 목적지 `winter_battle`(11개월차, 겨울 그림자 늑대 보스전) + 신규 `AdventureEngine:'battle'` + 순수 로직 `game/adventure/battle.ts`(진짜 플레이어/적 HP, 턴 루프, GDD 4카드가 실제 행동으로 작동) + `AdventureRunner`에 `BattleView` UI 추가. 3v3 진형은 여전히 없음(1v1로 스코프 유지) — `NOTES.md` 하단 업데이트 참고. 테스트 25건 추가, 목적지 수 10→11에 따른 기존 테스트 10건 갱신.
   GDD SCR-07 그대로(진형 3v3 + 카드 덱 + 적 AI + 턴 순서)를 만들면 사실상 새 게임 하나 규모다. 다음 중 하나를 스스로 판단해 선택하고 주석으로 범위를 명시한 뒤 구현한다:
   (a) 기존 `AdventureRunner`의 `guardian_sanctum` 시련처럼, 스킬 카드 4장을 실제 턴마다 드로우해서 고르는 "약식 카드 전투" 1개 신규 모험 스테이지 엔진(`AdventureEngine`에 `'cards'` 추가) — 상대 HP 게이지 하나만 있는 미니 보스전 형태로 스코프를 좁힌다.
   (b) 전투 시스템은 보류하고 그 사유를 `NOTES.md` 또는 코드 주석에 남기고 다음 항목으로 넘어간다.
   effort 예산이 부족하면 (b)를 선택해도 된다 — 단, 반드시 그 판단 근거를 기록한다.

5. ✅ **월간 목표/업적/엔딩 갤러리 카드 비주얼 통일 — 검토 후 변경 없음(의도적).** `.lh-panel-list>div`(정보 나열용 평면 행)와 `.wardrobe-card`/`.recipe-card`/`.hunt-card`/`.goal-card`(탭 가능한 입체 카드)를 비교한 결과, 스타일 차이는 비일관성이 아니라 상호작용 가능 여부에 따른 의도된 위계였다. 강제로 통일하면 오히려 "누를 수 있어 보이는 정보 행"이 생겨 UX가 나빠지므로 변경하지 않음. `EndingScreen`의 다크 테마도 그 화면 배경과 맞춘 의도된 분리로 판단.
